# CLI и выполнение команд

## Цель

Понять, как shell находит и запускает команду, как передаются аргументы и почему результат процесса определяется не только текстом вывода.

## Prerequisites

`01-Linux-Architecture.md`.

## In scope

При вводе команды shell выполняет несколько шагов: разбирает quoting и metacharacters, проверяет aliases/functions/builtins, ищет исполняемый файл по `PATH`, создаёт процесс и подключает его стандартные потоки.

```text
Строка shell
  ↓ parsing
Команда и аргументы
  ↓ lookup
Builtin, function или executable
  ↓ fork/exec
Процесс
  ├── stdin
  ├── stdout
  └── stderr
```

`PATH` — список каталогов, а не список конкретных программ. Shell проверяет их по порядку, поэтому неожиданная версия бинарника часто связана с PATH или alias. `command -v` показывает, что будет запущено, а `type` дополнительно различает builtin, alias и функцию.

Аргументы передаются процессу как массив строк. Shell разворачивает переменные, glob и substitutions до запуска, если это не запрещено кавычками. Поэтому `"$file"` безопаснее `$file`, когда значение может содержать пробелы или wildcard.

## Exit code

Процесс возвращает целое значение; ноль обычно означает успех, ненулевое значение — ошибку или особое состояние. Это контракт между программой и вызывающим shell. Проверка выполняется через `$?`, но в скриптах лучше сразу использовать `if command; then ...; fi` или сохранять код в переменную.

## Типичные ошибки

- запуск не той версии бинарника из-за `PATH`;
- потеря аргумента из-за отсутствия кавычек;
- ожидание, что shell builtin можно найти через `which`;
- игнорирование stderr;
- продолжение pipeline после скрытой ошибки без проверки exit code.

## Диагностика

```bash
type -a python3
command -v systemctl
printf '%s\n' "$PATH"
```

Команды диагностики должны отвечать на вопрос: что именно будет запущено, от какого пользователя и с какими аргументами.

## Практика

Создайте две команды с одинаковым именем в разных каталогах, измените `PATH`, проверьте результат через `type -a`, затем вызовите конкретный путь напрямую.
