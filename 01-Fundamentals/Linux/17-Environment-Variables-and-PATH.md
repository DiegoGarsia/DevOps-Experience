# Переменные окружения и `PATH`

## Цель

Понять, как процесс получает конфигурацию от родителя и почему окружение интерактивной сессии отличается от окружения `systemd`, cron или CI runner.

## Prerequisites

Users/groups, CLI и запуск процессов.

## In scope

Environment — набор строк `NAME=value`, передаваемый процессу при запуске. Дочерний процесс наследует копию окружения родителя, но изменение переменной после запуска не меняет уже созданный процесс. `export` делает переменную доступной дочерним процессам текущего shell.

`PATH` содержит список каталогов, в которых shell ищет исполняемый файл. Порядок имеет значение. Пустой элемент может означать текущий каталог и создавать security risk, поэтому не следует добавлять `.` без необходимости.

Окружение удобно для runtime configuration, но не является безопасным хранилищем секретов: его могут видеть `/proc`, crash dump, диагностические инструменты и дочерние процессы. Для секретов нужны отдельные механизмы доставки и rotation.

```bash
printenv | sort
export APP_ENV=staging
command -v curl
env -i PATH=/usr/bin:/bin /usr/bin/env
```

## Источники конфигурации

Interactive shell может читать startup files, SSH-сессия — свои правила, `systemd` — unit environment и drop-ins, CI — variables/secrets. Нельзя предполагать, что переменная, видимая в терминале, будет доступна сервису.

## Типичные ошибки

- хранить пароль в `PATH` или обычном environment;
- менять `.bashrc` и ожидать изменения уже запущенного сервиса;
- использовать относительный путь в non-interactive process;
- не фиксировать обязательные переменные в контракте приложения.

## Диагностика

Сравните `env` интерактивной сессии с `/proc/$PID/environ` и environment сервиса. Проверяйте фактический executable через `command -v` и полный путь.

## Практика

Создайте сервис с разным окружением для shell и `systemd`, найдите расхождение и оформите явный конфигурационный контракт.
