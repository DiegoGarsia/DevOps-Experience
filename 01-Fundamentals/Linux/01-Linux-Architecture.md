# Архитектура Linux

## Цель

Понять, как Linux связывает пользовательские программы, системные вызовы, ядро, драйверы и устройства.

## Prerequisites

Модель компьютерной системы и базовый CLI.

## In scope

Linux состоит из user space и kernel space. В user space работают shell, сервисы, библиотеки и приложения. Ядро управляет процессами, виртуальной памятью, планированием CPU, сетью, файловыми системами и устройствами.

Приложение обращается к ядру через system calls. Например, `open()` получает файловый дескриптор, `read()` запрашивает данные, `socket()` создаёт сетевой endpoint, `fork()` создаёт процесс. Системный вызов не означает обязательное физическое обращение к устройству: результат может находиться в page cache.

Ключевые абстракции Linux:

- процесс и thread;
- виртуальное адресное пространство;
- file descriptor;
- filesystem и mount;
- socket;
- user/group и permission;
- namespace и cgroup.

Ядро также предоставляет виртуальные представления состояния системы, прежде всего `/proc` и `/sys`. Они не являются обычными файлами на диске, хотя читаются похожими командами.

```text
Программа
  ↓ библиотека
System call
  ↓
Kernel subsystem
  ├── scheduler
  ├── memory manager
  ├── VFS
  ├── network stack
  └── driver
  ↓
CPU, RAM, disk, NIC или другое устройство
```

## Границы привилегий

Обычный процесс не должен напрямую менять память другого процесса, таблицы маршрутизации или содержимое диска. Для таких операций нужны права и переход в kernel space. `root` расширяет полномочия, но не отменяет ограничения ядра, файловой системы, capabilities и security modules.

## Типичная ошибка мышления

«Сервис запущен» не означает «сервис доступен». Процесс может быть жив, но не слушать порт, не иметь доступа к файлу, быть заблокированным на I/O или не проходить health check.
