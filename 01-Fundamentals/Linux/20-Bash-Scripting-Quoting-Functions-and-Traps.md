# Bash scripting: quoting, functions и traps

## Цель

Научиться писать небольшие предсказуемые Bash-скрипты для automation и diagnostics, понимая их ограничения.

## Prerequisites

Shell execution, variables, pipes, redirection и exit codes.

## In scope

Безопасный минимальный каркас:

```bash
#!/usr/bin/env bash
set -Eeuo pipefail

cleanup() {
  rm -f -- "$tmp_file"
}
trap cleanup EXIT
```

`-e` останавливает скрипт при ошибке, но имеет исключения в условиях и pipeline. `-u` выявляет обращение к несуществующей переменной. `pipefail` сохраняет ошибки внутри pipeline. Эти опции повышают предсказуемость, но не заменяют явную проверку критических операций.

Quoting защищает значения от word splitting и glob expansion. Для временных файлов используйте безопасное создание, для удаления — `--` перед пользовательским путём. Функции уменьшают повторение и позволяют возвращать status через `return`.

`trap` регистрирует обработчик сигнала или события shell. `EXIT` полезен для cleanup, `INT` и `TERM` — для корректного завершения. Обработчик не должен скрывать исходную ошибку и должен быть идемпотентным.

Параметры скрипта читаются через `"$@"`, а не через одну строку `$*`, если требуется сохранить границы аргументов. Валидация входа должна происходить до изменения системы.

## Типичные ошибки

- `rm -rf "$DIR"/*` при пустой или неверной переменной;
- отсутствие кавычек вокруг путей;
- установка `set -e` без понимания условных конструкций;
- cleanup, который падает и скрывает основную ошибку;
- скрипт, который нельзя повторно запустить.

## Диагностика

Используйте `bash -n` для синтаксиса, `shellcheck` для типичных ошибок, `set -x` временно для трассировки. Секреты не должны попадать в trace и CI logs.

## Практика

Напишите идемпотентный скрипт подготовки каталога и конфигурации. Добавьте проверку аргументов, cleanup через `trap`, dry-run режим и сценарий прерывания.
