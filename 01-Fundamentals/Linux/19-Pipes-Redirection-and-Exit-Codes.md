# Pipes, redirection и exit codes

## Цель

Понять, как shell соединяет процессы потоками и как корректно передавать результат одной команды другой.

## Prerequisites

Shell execution, file descriptors и текстовые потоки.

## In scope

`>` создаёт или перезаписывает stdout-файл, `>>` добавляет в него, `<` подключает файл к stdin, `2>` перенаправляет stderr. `2>&1` дублирует текущую цель stdout для stderr; порядок перенаправлений поэтому важен.

Pipe `|` соединяет stdout одного процесса со stdin другого. Это не передача всех данных «после завершения»: процессы могут работать одновременно, а буфер pipe ограничен. Если потребитель не читает данные, производитель может заблокироваться.

Код завершения доступен в `$?`, а для pipeline Bash может использовать код последней команды. `set -o pipefail` делает pipeline ошибочным, если завершилась ошибкой любая его существенная команда.

```bash
set -o pipefail
generate-data | validate-data > result.txt 2> errors.log
status=$?
```

Ошибки нужно направлять туда, где их сможет увидеть оператор или система мониторинга. Перенаправление stderr в `/dev/null` допустимо только при осознанном решении.

## Типичные ошибки

- путать `>` и `>>`;
- использовать `2>&1` до подключения stdout к нужному месту;
- считать exit code pipeline кодом первой команды;
- скрывать ошибку через `|| true`;
- не учитывать SIGPIPE при раннем завершении потребителя.

## Диагностика

Проверяйте `PIPESTATUS` Bash, временно сохраняйте промежуточные данные и запускайте стадии отдельно. Для production script фиксируйте команду и её код завершения.

## Практика

Постройте pipeline с намеренно падающей стадией. Сравните результат без `pipefail` и с ним, затем направьте stdout и stderr в разные файлы.
