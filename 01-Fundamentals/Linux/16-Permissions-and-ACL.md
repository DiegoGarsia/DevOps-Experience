# Permissions и ACL

## Цель

Научиться объяснять результат проверки доступа, а не менять права методом проб и ошибок.

## Prerequisites

Пользователи, группы и разрешение путей.

## In scope

Базовые mode bits состоят из прав владельца, группы и остальных: `r` — чтение, `w` — изменение, `x` — выполнение для файла или поиск для каталога. Для каталога `r` позволяет перечислять имена, `w` — создавать/удалять записи при наличии `x`, `x` — проходить внутрь.

Для исполняемого файла применяются effective UID/GID процесса. `umask` убирает нежелательные биты при создании. Setuid/setgid и sticky bit имеют специальную семантику и требуют отдельной оценки риска.

ACL расширяет модель дополнительными правилами для пользователей и групп. Mask ограничивает максимальные права named users, named groups и group class. Поэтому отображаемая ACL запись не всегда означает фактически полученный доступ.

```bash
stat file
namei -l /path/to/file
getfacl file
setfacl -m u:deploy:r file
```

Проверка должна идти по каждому компоненту пути, затем по owner/group/other, ACL, mount options, credentials и security policy.

## Типичные ошибки

- давать `777` вместо объяснения причины;
- забывать права поиска на родительском каталоге;
- неверно трактовать ACL mask;
- использовать setuid без threat model;
- исправлять права на runtime-сокет, не понимая последствий группы.

## Практика

Создайте каталог для приложения, разрешите одной группе запись, отдельному пользователю — чтение через ACL, затем проверьте доступ и объясните каждый результат.
