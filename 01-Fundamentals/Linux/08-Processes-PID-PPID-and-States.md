# Процессы, PID, PPID и состояния

## Цель

Понять жизненный цикл процесса и уметь отличать его состояние от состояния приложения, которое он обслуживает.

## Prerequisites

Архитектура Linux и file descriptors.

## In scope

Процесс — это экземпляр программы, которому ядро выделило виртуальное адресное пространство, идентификатор, credentials, descriptors и другие ресурсы. `PID` идентифицирует процесс в его PID namespace, `PPID` обычно указывает на родительский процесс.

Типичная цепочка:

```text
fork/clone → наследование контекста → execve → выполнение → exit → reap
```

После `fork` появляется копия процесса. `execve` заменяет его адресное пространство новой программой. Завершившийся процесс становится zombie, пока родитель не заберёт exit status через `wait`. Если родитель исчез, процесс может быть усыновлён специальным init-процессом.

Основные состояния Linux:

- `R` — runnable или выполняется;
- `S` — interruptible sleep;
- `D` — uninterruptible sleep, часто ожидание I/O;
- `T` — stopped;
- `Z` — zombie.

Состояние `D` не доказывает неисправность приложения: нужно найти ресурс, которого оно ждёт. Большое количество `Z` указывает на проблему обработки дочерних процессов, а не на «утечку памяти».

## Диагностика

```bash
ps -eo pid,ppid,stat,etime,cmd --forest
pstree -ap
cat /proc/$PID/status
```

Сначала фиксируйте PID, PPID, state и время жизни, затем связывайте процесс с service manager, портом, файлами и логами.

## Типичные ошибки

- убивать родителя, не понимая судьбу дочерних процессов;
- принимать zombie за работающий сервис;
- считать `D` обычным sleeping;
- смотреть только на имя процесса без его аргументов и namespace.

## Практика

Создайте процесс, который порождает дочерний процесс, временно остановите его, завершите родителя и исследуйте изменения `PPID` и состояния.
