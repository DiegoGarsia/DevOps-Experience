# Память и виртуальная память

## Цель

Понять, почему процесс видит виртуальный адрес, как ядро сопоставляет его с физической памятью и почему `free` нельзя читать как простой счётчик свободных байт.

## Prerequisites

Процессы, threads и `/proc`.

## In scope

Каждый процесс получает собственное виртуальное адресное пространство. Страницы виртуальной памяти отображаются в физические frames через page tables. MMU и TLB ускоряют это сопоставление. Адресное пространство содержит code, heap, stack, shared libraries и mappings файлов.

Виртуальная память даёт:

- изоляцию процессов;
- ленивое выделение страниц;
- copy-on-write после `fork`;
- memory-mapped files;
- возможность использовать больше логического адресного пространства, чем доступно физической RAM.

`RSS` показывает страницы процесса, находящиеся в RAM, но shared pages могут учитываться у нескольких процессов. `VSZ` — размер виртуального адресного пространства, а не объём реально занятой RAM.

Linux использует свободную память для cache. Поэтому низкое значение `free` само по себе не означает проблему. Важнее `available`, reclaimable cache, major faults, swap activity и pressure.

## Диагностика

```bash
free -h
ps -eo pid,rss,vsz,%mem,cmd --sort=-rss | head
cat /proc/$PID/smaps_rollup
vmstat 1
```

При анализе задавайте вопрос: это активные anonymous pages, file-backed pages, shared memory или cache, который можно освободить?

## Типичные ошибки

- считать VSZ реальным потреблением RAM;
- складывать RSS процессов без учёта shared pages;
- считать весь page cache утечкой;
- увеличивать RAM, не определив тип pressure;
- игнорировать NUMA и ограничения контейнера на следующих уровнях.

## Практика

Запустите программу, которая выделяет память и отображает файл через `mmap`. Сравните VSZ, RSS, cache и изменения после освобождения данных.
