# Структурированная конфигурация: JSON, YAML и TOML

## Цель

Научиться выбирать формат конфигурации и безопасно работать с типами, вложенностью, defaults и секретами.

## Prerequisites

CLI, текстовые потоки и базовая автоматизация.

## In scope

JSON строго описывает objects, arrays, strings, numbers, booleans и `null`. Он хорошо подходит для API и машинного обмена, но не имеет комментариев и удобных anchors.

YAML удобен для конфигурации и поддерживает comments, списки, mappings и anchors, но чувствителен к indentation и может неожиданно преобразовывать типы. Безопасный parser должен отключать выполнение произвольных объектов.

TOML явно описывает scalars, arrays и tables и хорошо подходит для конфигурации инструментов, где важна читаемость.

Конфигурация должна иметь schema, обязательные поля, значения по умолчанию и порядок precedence. Секреты не следует коммитить в открытом виде; файл конфигурации должен отделять secret references от обычных параметров.

## Типичные ошибки

- невалидный YAML из-за отступов;
- строка вместо числа или boolean;
- duplicate keys;
- секрет в Git или CI log;
- отсутствие версии схемы.

## Диагностика

Выполняйте parser/linter до применения, проверяйте типы и делайте dry-run. Сравнивайте rendered configuration с ожидаемой, но не печатайте секретные значения.

## Практика

Опишите конфигурацию сервиса в YAML и JSON, проверьте schema, добавьте обязательное поле и намеренно внесите ошибку типа.
