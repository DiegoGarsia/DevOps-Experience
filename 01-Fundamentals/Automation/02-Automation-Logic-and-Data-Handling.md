# Логика автоматизации и обработка данных

## Цель

Освоить мышление небольшого automation tool: вход, валидация, действие, результат, ошибка и повторный запуск.

## Prerequisites

Structured configuration, CLI, exit codes и Bash basics.

## In scope

Надёжный automation script разделяет:

1. получение входов;
2. проверку обязательных параметров;
3. чтение текущего состояния;
4. сравнение с желаемым состоянием;
5. минимальное изменение;
6. проверку результата.

Idempotency означает, что повторное выполнение при том же исходном состоянии не создаёт дополнительного нежелательного эффекта. Это не значит, что команда всегда ничего не делает: она должна изменить систему, если состояние не соответствует желаемому.

Ошибки должны быть классифицированы: invalid input, temporary dependency failure, permission error, conflict или invariant violation. Для временной ошибки возможен ограниченный retry с backoff, но не бесконечное повторение.

Данные при обработке нужно валидировать по schema, сохранять correlation ID и исключать секреты из логов. Для destructive action полезны dry-run, confirmation и rollback plan.

## Пример алгоритма

```text
получить конфигурацию
  ↓
проверить типы и обязательные поля
  ↓
прочитать текущее состояние
  ↓
вычислить diff
  ↓
если diff пуст — завершить успехом
иначе применить минимальное изменение
  ↓
проверить состояние повторно
```

## Типичные ошибки

- считать успешный exit code доказательством нужного состояния;
- изменять систему до валидации всех входов;
- retry неидемпотентной операции;
- не ограничивать время и число попыток;
- скрывать частичный успех.

## Практика

Напишите программу, которая создаёт каталог и конфигурационный файл только при необходимости, показывает diff в dry-run и корректно повторяется.
