# MTU, fragmentation и Path MTU

## Цель

Понимать, почему пакет может проходить через одну сеть и теряться на другом участке пути, и как MTU влияет на TCP и UDP.

## Prerequisites

IP, routing и TCP lifecycle.

## In scope

MTU — максимальный размер IP-пакета, который интерфейс или link передаёт без дополнительного разделения. Ethernet часто использует 1500 байт, но VLAN, VPN, туннели и overlay-сети уменьшают эффективный размер.

IPv4 может фрагментировать пакет, если он больше MTU следующего участка. Фрагменты собираются у получателя, а потеря одного фрагмента делает исходный пакет неполным. IPv6 routers не фрагментируют транзитные пакеты.

Path MTU — минимальный MTU по всему пути. TCP обычно узнаёт его через MSS и PMTUD. Если ICMP сообщения о слишком большом пакете фильтруются, возникает black-hole MTU: handshake проходит, а передача крупных данных зависает.

## Диагностика

```bash
ip link show dev eth0
tracepath 203.0.113.10
ping -M do -s 1472 203.0.113.10
tcpdump -ni any 'icmp or icmp6'
```

Размер payload в `ping` не равен полному размеру IP-пакета: учитывайте заголовки. Тестируйте несколько размеров и обе стороны пути.

## Типичные ошибки

- уменьшать MTU на одном интерфейсе без проверки маршрута;
- блокировать ICMP «для безопасности»;
- считать успешный TCP handshake доказательством корректного PMTU;
- путать MSS и MTU.

## Практика

Создайте туннель с уменьшенным MTU, найдите максимальный проходящий пакет, включите фильтрацию ICMP и зафиксируйте разницу в поведении малого и большого HTTP-ответа.
