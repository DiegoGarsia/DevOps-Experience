# IP-адресация, subnetting и CIDR

## Цель

Научиться определять границы подсети, broadcast, диапазон host-адресов и влияние маски на routing decision.

## Prerequisites

Ethernet, MAC и ARP.

## In scope

IPv4-адрес состоит из 32 бит. CIDR-запись `/n` показывает, сколько старших бит относится к network prefix, а оставшиеся — к host part. Адрес сети получается обнулением host bits, broadcast — установкой их в единицу.

Например, для `192.0.2.64/26`:

- mask: `255.255.255.192`;
- размер блока: 64 адреса;
- network: `192.0.2.64`;
- broadcast: `192.0.2.127`;
- обычный диапазон host: `192.0.2.65–192.0.2.126`.

Longest prefix match определяет, какой маршрут наиболее специфичен. Неверная маска может привести к ARP вместо gateway, отправке пакета не туда или невозможности достичь соседа.

Частные диапазоны RFC 1918 не маршрутизируются напрямую в публичном интернете. Loopback, link-local и multicast имеют отдельную семантику.

## Диагностика

```bash
ip -4 addr
ip route get 192.0.2.10
ipcalc 192.0.2.64/26
```

При ошибке проверяйте фактический адрес интерфейса, prefix length и маршрут, а не только строку конфигурации.

## Типичные ошибки

- путать `/24` с количеством доступных host;
- считать первый и последний адрес обычными host в каждой сети без исключений;
- смешивать network address и gateway;
- использовать перекрывающиеся подсети;
- забывать, что IPv6 имеет другую модель адресации.

## Практика

Разделите `10.10.0.0/24` на четыре равные подсети, укажите network/broadcast/host range и настройте два Linux-интерфейса с корректными prefix lengths.
