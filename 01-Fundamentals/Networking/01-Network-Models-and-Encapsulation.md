# Сетевые модели и инкапсуляция

## Цель

Получить модель, по которой можно локализовать сетевую проблему по слоям, а не проверять команды в случайном порядке.

## Prerequisites

Модель компьютерной системы и базовый CLI.

## In scope

Сеть можно рассматривать как несколько взаимосвязанных уровней:

- link — передача кадров в локальном сегменте;
- network — адресация и доставка IP-пакетов между сетями;
- transport — TCP или UDP и логические порты;
- application — DNS, HTTP, TLS и протокол конкретного сервиса.

При передаче данные инкапсулируются:

```text
HTTP data
  ↓ TLS record
TCP segment
  ↓ IP packet
Ethernet frame
  ↓
Physical medium
```

Каждый слой добавляет заголовок и снимает его на соответствующем узле. Ошибка в ARP не исправляется настройкой HTTP, а правильный DNS не гарантирует успешный TCP connect.

## Диагностическая модель

При симптоме «сервис недоступен» двигайтесь от границы клиента к приложению:

1. существует ли интерфейс и link;
2. есть ли маршрут;
3. разрешается ли имя;
4. устанавливается ли TCP;
5. проходит ли TLS;
6. отвечает ли HTTP;
7. корректно ли работает приложение.

## Типичные ошибки

- смешивать DNS failure и TCP failure;
- считать ping проверкой HTTP-доступности;
- проверять только локальный host, игнорируя промежуточный маршрут;
- изменять firewall до фиксации фактов.

## Практика

Нарисуйте путь запроса к тестовому HTTP-сервису и для каждого слоя укажите наблюдение, инструмент проверки и возможную ошибку.
