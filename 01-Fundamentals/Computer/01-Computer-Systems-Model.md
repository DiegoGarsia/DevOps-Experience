# Модель компьютерной системы

## Цель

Понять минимальную модель компьютера, на которой строится дальнейшее изучение Linux, виртуализации и контейнеров.

## Prerequisites

Не требуются.

## In scope

Компьютер можно рассматривать как взаимодействие процессора, памяти, устройств ввода-вывода, шин и программного кода. Процессор выполняет инструкции, но приложение почти никогда не работает с устройством напрямую. Между ними находятся драйвер, ядро операционной системы и механизмы защиты.

Память условно разделяется на регистры, кэш процессора, оперативную память и постоянное хранилище. Чем ближе уровень к процессору, тем он быстрее и меньше. Файл на диске не является «памятью процесса»: чтобы программа прочитала файл, ядро организует I/O, использует page cache и возвращает данные в адресное пространство процесса.

Процесс — это выполняемая программа с собственным виртуальным адресным пространством и ресурсами. Ядро переключает процессы, предоставляет им системные вызовы и изолирует доступ. Пользовательский код выполняется в user space, а привилегированные операции переходят в kernel space.

Устройства представлены ядру через драйверы и абстракции: файловые дескрипторы, sockets, block devices и character devices. Благодаря этому программа работает с разными устройствами через похожий интерфейс.

## Основной поток выполнения

```text
Программа
    ↓ системный вызов
Ядро
    ↓ драйвер и планировщик
CPU / память / устройство
    ↓ результат
Процесс
```

## Почему это важно для DevOps

Высокая загрузка CPU, задержка диска, нехватка памяти и сетевой timeout — разные симптомы, даже если пользователь видит один HTTP 500. Инженер должен уметь связать симптом приложения с нижним уровнем, не смешивая CPU, memory pressure, I/O wait и network latency.

## Ограничения модели

Модель упрощает NUMA, кэш-когерентность, виртуализацию и детали драйверов. Эти темы не нужны для первого понимания, но модель должна быть достаточно точной, чтобы объяснять процессы, память, I/O и контейнерную изоляцию.

## Проверка понимания

1. Почему приложение не обращается к диску напрямую?
2. Чем отличается виртуальная память процесса от физической RAM?
3. Где проходит граница между user space и kernel space?
4. Почему одинаковый HTTP timeout может быть вызван разными нижними слоями?

## Практика

Нарисуйте путь чтения небольшого файла: приложение → системный вызов → ядро → page cache или диск → процесс. Отдельно отметьте, где возможны задержки.
