# Представление данных и CLI

## Цель

Научиться читать технические данные в текстовом интерфейсе и понимать, почему формат вывода важен для автоматизации и диагностики.

## Prerequisites

`01-Computer-Systems-Model.md`.

## In scope

CLI — это интерфейс, в котором программа принимает аргументы, читает stdin и возвращает stdout/stderr с exit code. Команда — не магия оболочки: обычно это исполняемый файл, shell builtin или функция оболочки. Поэтому одинаково важно различать вывод программы и сообщение shell.

Данные бывают текстовыми и бинарными. Текст удобен для человека и простых pipelines, но его формат может измениться. Для обмена между системами применяются структурированные форматы: JSON, YAML, TOML и табличные представления. Их нельзя бездумно обрабатывать регулярным выражением, если нужен надёжный разбор вложенной структуры.

CLI-инструмент обычно имеет:

- позиционные аргументы;
- именованные опции;
- stdin для входных данных;
- stdout для результата;
- stderr для диагностики;
- код завершения для автоматической оценки результата.

## Модель взаимодействия

```text
Пользователь или скрипт
    ↓ аргументы и stdin
CLI-программа
    ├── stdout: полезный результат
    ├── stderr: диагностика
    └── exit code: успех или ошибка
```

Нельзя считать отсутствие текста в stdout успехом: программа может завершиться с ошибкой, отправив сообщение только в stderr. Нельзя считать наличие текста ошибкой: успешная команда тоже может выводить предупреждения.

## Практические правила

1. Для машинной обработки выбирайте стабильный формат, если инструмент его предоставляет.
2. Не парсите человекочитаемый вывод, когда есть JSON или другой структурированный режим.
3. Отделяйте stdout от stderr.
4. Проверяйте exit code в скрипте.
5. Указывайте единицы измерения и временную шкалу при записи наблюдений.

## Типичные ошибки

- обработка YAML как произвольного текста;
- потеря пробелов и кавычек при передаче аргументов;
- смешивание диагностического вывода с данными;
- использование локализованного вывода в автоматизации;
- отсутствие проверки кода завершения.

## Проверка понимания

Почему pipeline, который визуально показывает ожидаемый текст, всё равно может завершиться с ошибкой? Какие данные лучше хранить в JSON, а какие — в обычном тексте?

## Практика

Возьмите любую CLI-команду, сохраните отдельно stdout и stderr, намеренно передайте неверный аргумент и зафиксируйте exit code. Затем сравните человекочитаемый и структурированный режимы вывода.
