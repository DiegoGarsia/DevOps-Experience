# Merge, fast-forward и conflicts

## Цель

Понять, как Git объединяет две линии истории и как безопасно разрешать конфликт без случайной потери изменений.

## Prerequisites

Branches, commits и refs.

## In scope

Fast-forward возможен, когда текущая branch является предком целевой точки: Git просто перемещает ref, не создавая merge commit. Если истории разошлись, обычный merge создаёт commit с двумя parents. В conflict Git не может автоматически выбрать содержимое.

```text
A---B  main
     \
      C---D  feature
```

После merge результат должен сохранять намерение обеих сторон. Конфликт разрешается не выбором «левой» или «правой» строки, а проверкой бизнес-логики и тестов.

```bash
git merge feature
git status
git diff --conflict=diff3
git add resolved-file
git commit
```

Если решение оказалось неверным, до завершения merge можно использовать `git merge --abort`. После commit исправление делается новым commit или revert, а не ручным удалением истории без причины.

## Типичные ошибки

- принимать вариант текущей ветки без понимания изменения feature;
- забывать проверить непреднамеренно удалённые строки;
- разрешать conflict только синтаксически;
- запускать merge при незакоммиченных несвязанных изменениях.

## Практика

Создайте две ветки с конфликтом в одном файле, разрешите его через diff3, запустите тест и покажите итоговую историю с merge commit.
